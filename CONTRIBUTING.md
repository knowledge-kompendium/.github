# Contributing to the Knowledge Kompendium

Thank you for helping. These rules apply to every repository in the `knowledge-kompendium` organization unless a repository provides its own CONTRIBUTING file.

## Before you start

- For anything beyond a typo, open an issue first so the change can be discussed before you invest in it.
- Specification changes (normative text) need an issue that states the problem, the proposed semantics, and any compatibility impact.

## Pull requests

- Branch from `main`; keep each pull request to one logical change.
- `main` is protected: changes land through reviewed pull requests with passing checks.
- Sign off each commit to certify the [Developer Certificate of Origin](https://developercertificate.org/) (`git commit -s`).
- Include tests for code changes and worked examples for semantic changes.
